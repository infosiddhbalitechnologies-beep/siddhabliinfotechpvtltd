## What we'll build

A complete ticket-management backend powering Contact, Careers, and Business Enquiry forms — all funneled into one unified Ticket system with admin dashboard, user tracking, and email notifications.

## Steps

**1. Enable Lovable Cloud** (Supabase backend) and set up an email domain so notifications can send.

**2. Database schema**

- `profiles` — user display info (auto-created on signup).
- `user_roles` (`user` / `admin`) with `has_role()` security-definer function.
- `tickets` — unified table for every submission with:
  - `ticket_number` (e.g. `AXY-2026-000123`) auto-generated by trigger from a sequence
  - `type` (`contact` | `career` | `enquiry`)
  - `status` (`open` | `in_progress` | `waiting_on_user` | `resolved` | `closed`)
  - `priority` (`low` | `normal` | `high` | `urgent`)
  - `subject`, `message`, contact info (name, email, phone, company)
  - `submitted_by` (nullable — guests allowed), `assigned_to` (admin user)
  - type-specific JSON payload (e.g. career role/CV link, enquiry budget/timeline)
  - timestamps + `resolved_at`
- `ticket_comments` — threaded replies (admin ↔ user), each with `is_internal` flag for admin-only notes.
- `ticket_status_history` — audit trail of every status/assignment change.
- `career_resumes` storage bucket (private) for resume uploads.

**3. RLS policies**

- Anyone can INSERT a ticket (public forms).
- Authenticated users SELECT only their own tickets/comments (via `submitted_by = auth.uid()` or matching email).
- Admins (via `has_role`) SELECT/UPDATE all tickets, assign, change status, post comments.
- Triggers auto-log status changes into history.

**4. Auth**

- Email/password signup + login at `/auth`.
- First admin assigned via a one-time SQL grant (you tell me the email, or I provide a snippet).
- `_authenticated/` layout protects user dashboard; `_authenticated/admin/` layout gates admin pages with `has_role('admin')`.

**5. Frontend wiring**

- `/contact` — wire existing form to `submit_ticket` server fn (type=contact). Shows the ticket number on success.
- `/careers` — apply form with resume upload to private storage (type=career).
- Add Business Enquiry form section (type=enquiry) — likely on `/contact` or its own block.
- `/track` (public) — guest lookup by ticket number + email.
- `/dashboard` (auth) — user's tickets list + detail view with comment thread.
- `/admin` (admin) — queue with filters (status/type/priority/assignee), bulk actions, detail view with status change, assignment, internal notes, reply-to-user.

**6. Email notifications** (via Lovable's built-in email infra)

- `ticket-created` — confirmation to submitter with ticket number + tracking link.
- `ticket-status-updated` — to submitter when admin changes status.
- `ticket-new-reply` — to submitter when admin posts a public comment; to assignee when user replies.
- `ticket-assigned` — to admin when assigned.

**7. Server functions** (`src/lib/tickets.functions.ts`)

- `submitTicket` (public) — validates with Zod, inserts ticket, sends confirmation email, returns ticket number.
- `trackTicket` (public) — looks up by ticket_number + email.
- `getMyTickets` / `getTicketDetail` (auth) — user-scoped.
- `listAdminTickets`, `updateTicketStatus`, `assignTicket`, `addComment` (admin-only middleware).

## Technical details

- TanStack Start server functions; admin routes use a `requireAdmin` middleware that composes `requireSupabaseAuth` + `has_role` check.
- Ticket number generated via Postgres sequence + `BEFORE INSERT` trigger: `AXY-{YYYY}-{padded 6-digit}`.
- Resume uploads: client gets signed upload URL from server fn, uploads directly to `career_resumes` bucket, admin gets signed download URL on demand.
- All public endpoints rate-limit-friendly (Zod max lengths, server-side validation).
